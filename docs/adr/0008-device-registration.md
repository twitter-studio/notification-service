# ADR-0008: 端末の登録と、トークンを持っていることの確かめ

Status: Accepted / 2026-11-04

## 背景

設計書 v1.1 の §4 は、`PUT /v1/devices/{id}` (アカウントのセッションとインストールの署名で、APNs のトークンと環境を登録・入れ替える) と `DELETE /v1/devices/{id}` (アカウントのセッションで止める) を求めている。ADR-0004 は、端末がそのトークンを持っていることを確かめるまで送らないと決め、確かめ方を API-002 に残した。トークンは秘密ではないので (ADR-0001)、トークンを知っているだけの人の登録で、本物の端末への通知を奪わせない。

## 決定

### 登録 (`PUT /v1/devices/{id}`)

- `{id}` はインストールの ID。v1 の端末はインストールごとに 1 つなので、アプリが知っている ID で指す。セッションのインストールでない ID は、あるかを区別せずに 404。
- アカウントのセッションと、端末の鍵の署名で行う (200)。
  - 署名する文は `twitter-studio/device/v1\n<チャレンジ>\n<インストールの ID>\n<環境>\n<topic>\n<トークン>\n<enabled>`。トークンは小文字の 16 進数。`enabled` は `true`、`false`、省いたら空。チャレンジは用途 `device` で出したもの。セッションだけで、ほかのトークンや環境、設定に書き換えさせない。
  - チャレンジは、端末の行の書き込みと同じバッチで使ったものとして記録する (2 回目は 409)。
- 環境は `sandbox` と `production` のどちらも受ける (開発のビルドは sandbox)。topic (Bundle ID) は、設定 `APNS_TOPICS` (カンマ区切り、`wrangler.jsonc` の vars) にあるものだけを受ける (ほかは 422)。
- トークンは ADR-0005 のとおり、端末の行に結び付けて暗号化し、指紋と一緒に置く。
- `enabled` (省いてよい): `true` で通知を受け取る、`false` で止める。省くと今のまま。アプリは起動のたびにトークンを送り直すので、トークンの入れ替えで、利用者が止めた設定を戻さない。
- 応答は、端末の ID、状態、確かめたか、確かめの push を送ったか。

### トークンを持っていることの確かめ

- 登録した端末を確かめていなければ、確かめの code (`tsv_` と 32 バイトの乱数) を作り、push で端末に送る。
  - DB (`device_verifications`) には、code の SHA-256 と、code を送るトークン (この要求の指紋、環境、topic)、期限 (10 分) を置く。端末ごとに 1 つで、送り直したら置き換える。
  - 記録は、端末の行が今そのトークンで、まだ確かめていないときだけ置き、置けたときだけ push を送る。行の値を写すと、同じインストールの登録が並んだとき (トークン A の登録と B の登録)、行の B の値で記録を作り、その code を A へ送ってしまう。A の持ち主 (攻撃する人) がその code を返すと、B を確かめたことになり、B の本物の端末への通知を奪える (セキュリティのレビューで、並べて送るだけで再現した)。
- アプリは、届いた code を `POST /v1/devices/{id}/verification` (アカウントのセッション) で返す。設計書の API の一覧にはないので、ここで足す。
  - `markDeviceVerified` は、code のハッシュが期限内の記録と合い、記録のトークンが今の端末と合い、自分のアカウントの有効なインストールの端末のときだけ、確かめたことにする。突き合わせは書き込みと同じ文の中で行い、記録 (証明) なしには呼べない。
  - 同じトークンを確かめていたほかの行は、確かめを外す (ADR-0004 の引き継ぎ)。push はトークンの持ち主の端末にだけ届くので、トークンを知っているだけの人は code を受け取れず、引き継げない。
  - code は 1 回だけ使える。合った記録は、確かめられたかに関わらず消す。違う code、期限切れ、トークンが変わった後の code は 422。
- 確かめの push の形 (background push か、通知の拡張で受けるか、code を入れるキー) は、APNs へ送る仕組み (APNS-002) とアプリ (IOS-001) で決める。background push は iOS が遅らせたり落としたりすることがある。届かなければ、アプリは同じトークンで登録し直して、新しい code を送らせる。
- APNs へ送る仕組みができるまでは、確かめの push を送らない (`verification_sent: false`)。端末は確かめないままで、通知も送らない。

### 止める (`DELETE /v1/devices/{id}`)

- アカウントのセッションで行う (204)。端末の状態を `disabled_by_user` にする。端末がない、セッションのインストールでないときは 404。

### 回数の制限

- 登録: インストールごと (`INSTALLATION_RATE_LIMITER`、`device:<インストールの ID>`、1 分に 5 回)。署名を確かめた後に数える。
- 確かめの push: トークンごと (`TOKEN_RATE_LIMITER`、1 分に 10 回)。確かめの push は、トークンを知っていればどのアカウントからでも送らせられるので、アカウントをまたいで数える。
  - push を実際に送るときだけ数える (確かめ済みの登録し直しや、通知を戻す登録は数えない)。超えたら push を送らず、登録は通す (`verification_sent: false`)。ほかの人に、持ち主の登録を 429 にさせない。
  - 1 つのインストールが 1 つのトークンへ送れるのは、登録の制限の 5 回まで。全体の枠 (10 回) を 1 つのインストールでは使い切れない。いくつものアカウントで使い切られると、持ち主の確かめの push が遅れる (持ち主は、後で登録し直す)。枠を見てから確かめの記録を置くので、枠が埋まっているあいだの登録し直しで、届いている code は消えない。
  - 枠の数は Cloudflare の場所ごとなので、ほかの人のトークンへ送りつけられる量は、使う場所の数だけ増える。招待制のあいだは、これで足りるとする。登録を開くとき (AUTH-003) に、トークンごとの時間単位の上限を DB で持つかを考える。
  - 数える単位には、指紋そのものではなく、指紋の短いハッシュを使う。
- 確かめ: セッションごと (`device-verification:<セッションの ID>`)。漏れたセッションで違う code を送り続けても、持ち主のほかのセッションの確かめを止めさせない。漏れたのが持ち主の今のセッションなら、そのセッションの確かめは止まるので、アプリは確かめで 429 を受けたら、セッションを作り直してからやり直す (IOS-001)。
- 止める: インストールごと (`device-disable:<インストールの ID>`)。漏れたセッションで通知を止められるのは、設計のとおり。アプリは、登録の応答の `state` を利用者の設定と比べ、食い違えば利用者に知らせる (IOS-001)。

### 消す

- 期限を過ぎた確かめの記録は、定期の掃除で消す (使ったチャレンジと同じく、時計のずれの幅を待つ)。
- インストールの取り消しとアカウントの削除では、端末の行の前に、確かめの記録も消す (外部キーは CASCADE にしていない。ADR-0004)。

## 採らなかった案

- **サーバーが決めた端末の ID を `{id}` にする**: アプリが、インストールの ID のほかに、端末の ID も覚えることになる。v1 は 1 対 1 なので、インストールの ID で足りる。
- **登録だけで送り先にする**: トークンは秘密ではない。トークンを知っている人が登録するだけで、本物の端末への通知を奪える。
- **アプリの署名だけで、トークンを持っていることにする**: 署名は鍵を持っていることの証明で、そのトークンが自分の端末に届くことの証明ではない。
- **code を平文で置く**: DB が漏れたとき、期限のあいだに、ほかの人の端末を確かめたことにできる。

## 影響

- APNs へ送る仕組み (APNS-002) は、`DeviceVerificationSender` を作り、`createApp` に渡す。
  - push には、宛先のインストール (または端末) の ID を入れる。アプリは、自分宛てでない code を返さない (ほかの人が送りつけた code で、自分の確かめの枠を使わない)。
  - code を、目に見える通知の文に入れない (人に code を読ませて返させる騙しを防ぐ)。送り手は、トークンと code をログに出さない。
- アプリ (IOS-001) は、上の文に署名して登録し、確かめの push を受けて code を返す。起動のたびにトークンを送り直す。
- 確かめるまで通知を送らないので、APNS-002 ができるまでは、本番でもどの端末にも送らない。
